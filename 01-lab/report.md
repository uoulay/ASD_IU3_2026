## 2. Организация кода

Каждая задача находится в отдельном пакете `ru.bmstu.lab1.task_<номер>` и состоит из одного класса. В начале файла приведены номер и формулировка задачи, формат ввода и вывода.

Класс каждой задачи разделён на две части:

- публичный статический метод с самим алгоритмом (например, `findSecondLargest`), который не связан с вводом-выводом;
- метод `main`, который читает данные из стандартного потока ввода и печатает ответ.

Такое разделение позволяет тестировать алгоритм напрямую, без ввода с клавиатуры, а `main` проверять отдельно.

Чтение массивов и матриц и печать результата вынесены в общий класс `ArrayIO`, чтобы не дублировать код в 25 файлах. Для тестов `main` используется вспомогательный класс `ProgramOutput`: он подставляет заранее заданный ввод и перехватывает напечатанный текст.

### Формат входных данных

Числа разделены пробелами или переводами строк.

| Тип входа | Формат |
|-----------|--------|
| Массив | `n`, затем n чисел |
| Массив и число (`x` или `k`) | `n x`, затем n чисел |
| Два массива | `n`, первый массив, второй массив |
| Прямоугольная матрица | `n m`, затем n строк по m чисел |
| Квадратная матрица | `n`, затем n строк по n чисел |

Если ответ пустой (нет подходящих индексов или удалены все элементы), печатается пустая строка.

## 3. Описание решений

Условие требует работать с массивами, поэтому дополнительные структуры данных (списки, множества, хеш-таблицы) не использовались. Во всех задачах достаточно обычных массивов и циклов, это же упрощает оценку асимптотики и расхода памяти.

### Линейный поиск и фильтрация (1–10)

Каждая задача решается одним или двумя проходами по массиву.

- **Минимум, максимум и второй максимум (1, 7).** Два текущих значения обновляются на каждом шаге, без сортировки. Это быстрее, чем сортировка, и не требует дополнительной памяти.
- **Поиск индекса (2, 10).** Первый индекс ищется слева направо с выходом из цикла при первом совпадении, последний кратный элемент — справа налево.
- **Подсчёт и суммы (3, 5, 6).** Один проход со счётчиком или суммой. В задаче 6 сначала считается сумма (для среднего), затем второй проход подсчитывает элементы строго больше среднего.
- **Все индексы и фильтрация по знаку (4, 8).** Размер результата заранее неизвестен, поэтому первый проход считает, сколько элементов подойдёт, второй заполняет массив нужной длины. Так обходимся без списков.
- **Проверка порядка (9).** Сравниваются соседние элементы, при первом нарушении возвращается `false`.

### Сортировки (13, 14, 15, 21)

- **Выбором (13)** и **вставками (14)** написаны вручную, как требует условие. Сортировка вставками выполняется по невозрастанию.
- **Пузырьком (15)** считает число обменов и завершается досрочно, если за проход не было обменов, то есть массив уже отсортирован.
- **K-й наименьший (21).** По условию массив сортируется, затем берётся элемент с индексом `k - 1`; используется стандартный `Arrays.sort`.

### Арифметика (25, 26, 27, 31, 36)

Суммы, сумма квадратов и скалярное произведение накапливаются в переменной типа `long`, так как результат может не поместиться в `int`. Приведение к `long` выполняется до умножения (`(long) a[i] * b[i]`), иначе произведение переполнилось бы раньше.

В задаче 26 остаток от деления на 10^9 + 7 берётся на каждом шаге, чтобы число не росло. Остаток отрицательного числа в Java отрицателен, поэтому к нему прибавляется модуль, и ответ всегда лежит в диапазоне от 0 до 10^9 + 6.

Бегущая сумма (36) использует предыдущий элемент результата: `totals[i] = totals[i - 1] + numbers[i]`.

### Преобразование массивов (37, 41)

- **Разворот (37)** выполняется на месте: два индекса идут с концов к середине, элементы меняются местами, новый массив не создаётся.
- **Удаление значения (41)** строит новый массив без элементов, равных `x`: сначала подсчёт оставшихся, затем заполнение.

### Матрицы (49, 50, 54, 55)

- Суммы строк и столбцов вычисляются двойным циклом, каждая ячейка просматривается один раз.
- Главная диагональ — элементы `matrix[i][i]`, побочная — `matrix[i][n - 1 - i]`. Проходится только n элементов, а не вся матрица.

## 4. Асимптотика

Подробный расчёт для каждой задачи приведён в файле `asymptotics.md`. Сводка:

| Задачи | Время | Доп. память |
|--------|-------|-------------|
| 1–3, 5–7, 9, 10, 25, 26, 27, 31 | O(n) | O(1) |
| 4, 8, 41, 36 | O(n) | O(n) (память под ответ) |
| 37 | O(n) | O(1) |
| 13 | O(n²) | O(1) |
| 14, 15 | O(n²) в худшем случае, O(n) если массив уже упорядочен | O(1) |
| 21 | O(n log n) | O(log n), в худшем случае до O(n) |
| 49, 50 | O(n·m) | O(n) и O(m) соответственно |
| 54, 55 | O(n) | O(1) |

Квадратичная сложность задач 13, 14 и 15 ожидаема: условие требует именно эти алгоритмы сортировки.

## 5. Тестирование

Для каждой задачи написан отдельный класс тестов на JUnit 5 (имя задачи с суффиксом `Test`). Имена тестов описывают проверяемое поведение, например `shouldReturnMinusOneWhenNumberIsMissing`. В каждом классе есть:

- тест типичного случая;
- тесты граничных случаев: отрицательные числа, равные элементы, ноль, значение в начале или в конце массива, пустой результат;
- тест `shouldReadArrayFromInput`, который запускает `main` с заданным вводом и проверяет напечатанный ответ, то есть проверяет формат ввода-вывода, а не только алгоритм;
- для задач с большими числами — отдельные тесты на переполнение (например, сумма `1500000000 + 1 + 1500000000` на чётных позициях равна `3000000000`; произведение `100000 · 100000` по модулю даёт `999999937`).

## 6. Запуск

Из корня модуля все тесты запускаются командой:

```
mvn clean test
```

Отдельная задача запускается через `main` соответствующего класса: данные вводятся с клавиатуры или подаются из файла в формате из раздела 2.

## 7. Допущения

В соответствии с условием (1 < n < 10^5) массивы считаются непустыми, содержащими как минимум два элемента, поэтому в задачах 7 и 36 дополнительная проверка на пустой массив не выполняется. В задаче 10 делитель `k` не равен нулю, в задаче 6 среднее арифметическое — целое число, в задаче 7 все элементы различны. Все эти ограничения заданы условием.
