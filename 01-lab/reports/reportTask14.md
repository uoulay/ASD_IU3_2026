## 1. Условие

Вход: массив из n целых чисел.
Выход: массив, отсортированный по невозрастанию.
Сортировку нужно написать самому.

Ввод:
n
a1 a2 ... an

Вывод: числа через пробел.

## 2. Идея решения

Левая часть массива считается уже отсортированной. Для каждого следующего элемента `current` внутренний цикл сдвигает вправо все элементы левой части, которые меньше `current`, и ставит `current` на освободившееся место. Так как нужен порядок по невозрастанию, сдвигаются именно меньшие элементы. Равные элементы не сдвигаются, значит сортировка устойчива.

## 3. Алгоритм в коде

```java
public static int[] sortDescending(int[] numbers) {
    for (int i = 1; i < numbers.length; i++) {
        int current = numbers[i];
        int j = i - 1;
        while (j >= 0 && numbers[j] < current) {
            numbers[j + 1] = numbers[j];
            j--;
        }
        numbers[j + 1] = current;
    }
    return numbers;
}
```

## 4. Анализ асимптотики

| | Оценка |
|---|---|
| Время (худший случай) | O(n²) в худшем случае, O(n) в лучшем |
| Дополнительная память | O(1) |

**Обоснование.** Внешний цикл делает n − 1 итераций. Внутренний `while` в худшем случае (массив отсортирован по возрастанию, то есть в обратном порядке для нашего условия) на шаге `i` сдвигает i элементов, всего n(n − 1)/2, это O(n²). Если массив уже стоит по невозрастанию, условие `numbers[j] < current` ложно сразу, внутренний цикл не выполняется ни разу, и получается O(n). Сортировка на месте: `current`, `j` и счётчик, O(1).

Входные данные записаны в формате, который читает `main` (первая строка — размеры, далее элементы). Ожидаемые ответы получены вручную до запуска программы, затем сверены с её выводом.
