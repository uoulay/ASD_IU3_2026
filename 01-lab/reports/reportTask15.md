## 1. Условие

Вход: массив из n целых чисел.
Выход: отсортированный массив и количество обменов.
Если массив уже отсортирован, сортировка останавливается раньше.

Ввод:
n
a1 a2 ... an

Вывод: сначала числа через пробел, на следующей строке — число обменов.

## 2. Идея решения

На каждом проходе соседние элементы сравниваются и при необходимости меняются местами, при этом счётчик `swaps` растёт. После прохода самый большой из оставшихся элементов оказывается в конце, поэтому каждый следующий проход короче (`numbers.length - 1 - pass`). Если за целый проход не было ни одного обмена, массив уже отсортирован, и цикл прерывается досрочно. Равные соседи не меняются, поэтому число обменов равно числу инверсий (пар i < j, где `a[i] > a[j]`).

## 3. Алгоритм в коде

```java
public static int sortAndCountSwaps(int[] numbers) {
    int swaps = 0;
    for (int pass = 0; pass < numbers.length - 1; pass++) {
        boolean swapped = false;
        for (int i = 0; i < numbers.length - 1 - pass; i++) {
            if (numbers[i] > numbers[i + 1]) {
                int temporary = numbers[i];
                numbers[i] = numbers[i + 1];
                numbers[i + 1] = temporary;
                swaps++;
                swapped = true;
            }
        }
        // Если за проход не было обменов, массив уже стоит по порядку.
        if (!swapped) {
            break;
        }
    }
    return swaps;
}
```

## 4. Анализ асимптотики

| | Оценка |
|---|---|
| Время (худший случай) | O(n²) в худшем случае, O(n) в лучшем |
| Дополнительная память | O(1) |

**Обоснование.** В худшем случае (массив по убыванию) выполняется n − 1 проходов, на проходе `pass` делается n − 1 − pass сравнений, всего n(n − 1)/2, это O(n²). Если массив уже отсортирован, первый проход не делает обменов, `swapped` остаётся `false`, и срабатывает `break`: всего n − 1 сравнение, это O(n). Память: `swaps`, `swapped`, `temporary` и счётчики, O(1).
